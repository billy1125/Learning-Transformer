# 教材分類體系重整：四大區 × 呈現層次雙軸

## Context

倉庫已累積 23 份理論文件（約 13,400 行）、5 份 Notebook、6 份 advanced 補充。編號體系 `00`–`10` 是隨內容增長逐份追加的，導致目前的導覽層有四個具體問題：

1. **README 的「完整路線圖」把平行的家族分支畫成一條直線**：`06 → 07 → 09` 之間用 `↓` 串接（README.md:118–129），讀者會誤以為要讀完 LLaMA 變體才能讀 BERT。實際上 06 是 decoder 家族出口、07 是 encoder 家族分支，兩者平行。
2. **Seq2Seq 四件套（10a1–10b2，約 3,130 行）完全沒出現在 README 的路線圖**，只躺在文件清單表格第 20–23 列。
3. **教材真正的第二條軸沒有被呈現**：同一份知識被切成「概念 / 符號數學 / 數值範例 / 程式對照」四層（`04a` / `05a1` / `05a2` / `04b`），這個規律藏在檔名後綴裡。README 用一張 23 列的平表列出，讀者看不出 `05a2` 是 `05a1` 的數值續篇、也看不出為何 `04b` 排在 `05a2` 之後。
4. **經典模型的說明是分散的**：BERT 家族在 `07` §6、LLaMA 在 `06`、T5/BART 只有一句話帶過、GPT-1/2/3 的世代演進幾乎沒講。沒有任何一處能一眼看到三大家族的全景與時間軸。
5. **缺「學完之後銜接到什麼」的落點**：教材把三家族的原理講透了，但沒說每一家在 2025 年的實際主戰場在哪——讀者不知道 encoder-only 的重心已從分類微調轉到 embedding model（BGE / E5 / gte）、也不知道 encoder-decoder 沒有消失而是轉進語音（Whisper）與翻譯（NLLB / M2M-100）。少了這一層，2C 支線的 3,130 行會顯得像是歷史考古。

另有兩個邊角：`advanced/` 6 份文件只有 1 份（`Seq2Seq-and-Decoding-Techniques.md`）寫了與主線的關係；`appendices/trig-reference.html` 完全沒被任何導覽提及。

**素材來源**：本計畫整合自 `draft/roadmap-transformer.md`（三分流架構與各家當代銜接，已併入後刪除）與 `draft/learning-route-notes.md`（難度分級、數學 Level 1–5、六階段路線，內容大多已在 `theory/00-learning-path.md`）。

**預期成果**：讀者從 README 或 `00` 進入時，能在 30 秒內回答「我現在在哪一區」「這一區的終點是什麼」「下一步有哪幾條平行的路」「這份文件是概念、數學、範例還是程式」。

**明確不做**：不改任何既有檔名、不改任何既有節號、不動既有文件的內文結構。`05a1`↔`05b1` 的倒序鏡射表、`10a1`/`10a2`/`10b1`/`10b2` 四份的節號鏡射表、`NB1`–`NB5` 對 `07 §n` 等的硬引用全部保持有效。

### 軸一：四大區（學習階段）

| 區 | 名稱 | 這一區在回答 | 終點（讀完能做到） | 成員 |

| 1 | 地基：一個 Transformer Block | 注意力怎麼算、Block 怎麼組 | 手算一個完整 Pre-LN Block | `01a`/`01b`、`02`、`03a`（+`03a-plain`、`03b1`–`03b4`）、NB1、NB2 |
| 2 | 三大家族 | 同一個 Block 怎麼變成三種模型 | 說出三家的遮罩與訓練目標差異，並手刻其中任一 | 2A `04a`/`05a1`/`05a2`/`05b1`/`05b2`/`04b`＋NB3/NB4；2B `07`＋NB5；2C `10a1`/`10a2`/`10b1`/`10b2` |
| 3 | 家族演進與模型家譜 | 2018 年之後各家怎麼進化 | 看懂 LLaMA/RoBERTa 的原始碼在改什麼 | `08`（新）、`06`、`07` §6 |

| — | 旁支資源（非路線）| — | — | `advanced/`、`appendices/` |

**區 2 的內部結構**（三條平行支線，共用區 1 的 Block）：

```
                區 1 終點：一個 Transformer Block
                            │
        ┌───────────────────┼───────────────────┐
   2A Decoder-only     2B Encoder-only     2C Encoder-Decoder
      GPT                  BERT               Seq2Seq / T5
   04a→05a1→05a2            07                10a1→10a2
   →05b1→05b2→04b                             →10b1→10b2
      NB3 / NB4             NB5                （實作待補）
        │                    │                    │
        └────────┬───────────┴─────────┬──────────┘
                 ▼                     ▼
          區 3 家族演進           區 4 系統層應用
        08 家譜 / 06 LLaMA          09 RAG
```

**要明講的兩句話**：

1. 三條支線的**深度刻意不對稱**。反向傳播只在 2A 完整推導一次（`05b1`/`05b2`），2B 直接共用，2C 只推「與 2A 不同的那部分」（BPTT 的時間鏈、cross-attention 的梯度分岔）。讀者不必擔心 2B 只有一份文件是漏寫。
2. 三條支線**今天都還活著，只是主戰場不同**——這是每一支的「為什麼要學」：

| 支線 | 2025 年的主戰場 | 代表 |
|---|---|---|
| 2A Decoder-only | 幾乎所有通用大型語言模型 | GPT-4、Claude、Gemini、LLaMA、Qwen |
| 2B Encoder-only | 重心已從「分類微調」轉到 **embedding model**，是 RAG 的檢索端 | BGE、E5、gte、Sentence-BERT |
| 2C Encoder-Decoder | 純文字生成上被 decoder-only 取代，但在**跨模態／跨語言**仍是主流 | Whisper（語音→文字）、NLLB、M2M-100、T5 |

2C 特別需要這句話：沒有它，`10a1`–`10b2` 那 3,130 行看起來會像歷史考古。

**閱讀順序的建議**（與現行主線一致，這裡只是把理由寫明）：先把 2A 做到會手刻（`04a`→`05a1`→`05b1`→`04b`＋NB4），再回頭讀 2B（差異只有兩處，一天可讀完），最後補 2C。原因是 2A 的反向推導最完整，另兩支都建立在它之上；而且 decoder-only 是目前投入產出比最高的一支。

### 軸二：呈現層次（同一主題的四種切法）

| 層次 | 標記 | 回答什麼 | 代表文件 |
|---|---|---|---|
| 概念 | 概 | 這是什麼、為什麼需要 | `04a`、`03a-plain`、`07` §0–§1、`08` |
| 符號數學 | 數 | 公式怎麼推出來 | `03a`、`05a1`、`05b1`、`10a1`、`10b1` |
| 數值範例 | 例 | 代真實數字算一次 | `03b1`–`03b4`、`05a2`、`05b2`、`10a2`、`10b2` |
| 程式對照 | 碼 | 公式對應到程式哪一行 | `04b`、NB1–NB5 |

這條軸順帶解釋了兩件目前讓人困惑的事：為何 `04b` 在閱讀順序上排在 `05a2` 之後（程式對照要等數學講完），以及為何 `03a` 之外還有 `03b1`–`03b4`（同一主題的「例」層，三階段遞進）。

### 對使用者原始構想的兩處修正

- **LLaMA 與 RAG 不同層級**。LLaMA 是 decoder 家族的當代演進（區 3，架構層）；RAG 是 encoder 檢索＋decoder 生成的系統組合（區 4，系統層）。兩者並列成「整合路線」會讓讀者以為 LLaMA 是三家融合的產物。
- **Encoder-Decoder 要當成第三個家族平列**，不是 decoder/encoder 之外的附註。原始 Transformer 就是這一支的祖先，`10a1`–`10b2` 已有 3,130 行的完整內容，值得在路線圖上取得與 2A/2B 同等的地位。
